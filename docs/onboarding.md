# 설치 후 저장소 연결 — alpha.6

테스트할 Git 저장소에서 새 Codex 세션을 열고 **“Handrail 설정해줘”**라고 요청한다. 터미널에서는 다음 명령 하나로 시작한다.

```sh
handrail init
```

| 단계 | Handrail의 처리 | 사용자 입력 |
| --- | --- | --- |
| 설치 확인 | 실제 bundle·skill 경로 확인 | 없음 |
| 호스트 연결 | 유효한 연결·HTTP 허용 선택 재사용 | 최초 서버 URL과 숨김 토큰 입력 |
| 실행 환경 | Herdr 발견, 작업 경로 선택·접근 확인 | 여러 후보 또는 실제 권한 부족 시만 |
| 부모 보드 | 접근 가능한 활성 프로젝트 전체의 이름·부모 경로·링크 표시 | 기존 보드 선택 또는 새 이름 |
| 보드 준비 | manual Kanban, 누락 열 생성, 기본/완료 열 매핑 | 모호한 뷰·열 선택 시만 |
| 연결 완료 | 바인딩 저장·최종 확인 | 구현할 작업 요청 |

내부 ID 수집과 매핑 JSON 작성은 일반 설정에 필요하지 않다. 비대화형 실행은 필요한 선택을 `SETUP_INPUT_REQUIRED`로 반환한다. 에이전트는 이름·링크로 질문하고 내부 값은 직접 전달한다.

새 저장소의 보드 선택은 후보가 하나이거나 저장소와 이름이 같아도 생략하지 않는다. 사용자 답변을 기다린 후 연결한다. 저장된 서버 연결 정보와 명령 실행 권한 승인은 보드 선택을 대신하지 않는다. 사용자가 요청에서 특정 보드를 이미 지정했다면 해당 선택을 재사용한다.

## 최초 연결

터미널 `init`은 URL·HTTP 허용 여부·토큰을 이어서 받는다. 에이전트가 설정할 때는 토큰만 사용자 터미널에서 입력한다.

```sh
handrail setup --url https://vikunja.example.com
handrail setup --url http://192.168.0.172:58821 --allow-insecure-http
```

HTTP 안내에는 반드시 허용 옵션을 포함한다. 연결 이름은 자동 지정하고 저장된 HTTP 선택은 재사용한다. `--insecure`는 `--allow-insecure-http`의 별칭이며 HTTPS 인증서 검사를 끄지 않는다. 토큰 교체는 `setup --replace-token`으로 진행한다.

## 보드와 칸반

```sh
handrail init --board '테스트 프로젝트'
handrail init --board http://192.168.0.172:58821/projects/18
handrail init --new-board '새 테스트 프로젝트'
```

위 예시는 사용자 대화형 터미널용이다. 에이전트의 비대화형 실행에서는 실제 사용자 선택을 받은 뒤 `--confirm-board-selection`을 함께 전달한다. 이 옵션 없이 `--board`만 전달하면 전체 목록과 선택 요청을 반환한다. 사용자에게 추가 옵션 입력이나 두 번째 확인을 요구하지 않는다. 옵션 자체가 대화의 진위를 검증하지는 않으므로 스킬에서도 실제 답변을 기다리도록 규정한다.

선택한 부모의 필터 없는 manual Kanban을 사용한다. 여러 후보는 선택을 받고, 적합한 뷰가 없으면 전용 뷰를 준비한다. 기존 열을 재사용하며 부족한 Todo/Doing/Review/Done 열을 생성한다. 다른 열·뷰를 삭제하지 않는다. 실제 프로젝트 쓰기 권한과 토큰의 관련 API 권한이 필요하다.

설정 완료 후 하위 보드가 필요하면 `handrail board add frontend backend`처럼 추가한다. 칸반 구성은 Handrail 자체 관리 기능이며 Plan·Work·작업자를 만들지 않는다. [보드·카드 관리](boards.md)에서 보드 추가와 사용자 요청 카드 상태 전환을 설명한다.

## Herdr·경로·권한

상속된 endpoint와 실제 존재하는 소켓을 조회한다. 여러 대상은 선택을 받으며 기존 endpoint를 조용히 교체하지 않는다. `HERDR_ENV=1`을 주입하거나 세션을 자동 시작하지 않는다.

기본 worktree는 checkout 옆 `.handrail-worktrees/<저장소 식별자>`다. 허용 경계 밖이면 필요한 접근 권한을 해결하거나 `--worktree-root`로 허용된 외부 영속 경로를 지정한다.

설정 중 checkout·Git common directory·비공개 상태·worktree에서 임시 파일 쓰기를 확인하고 필요한 디렉터리는 생성한다. IPC와 파일 접근 오류는 함께 보고한다. 이 확인은 설정 프로세스에만 해당하며 작업자의 별도 sandbox 권한은 증명하지 않는다. `doctor`와 `preflight`는 계속 읽기 전용이다.

## 중단 후 계속하기

같은 `init`을 다시 실행하면 저장된 연결·확인된 선택을 재사용한다. alpha.3 이전의 미완료 설정에 선택 기록이 없으면 다시 질문한다. 이미 바인딩된 저장소는 기존 연결을 유지하므로 목록 선택 흐름을 재테스트하려면 아직 연결하지 않은 Git 저장소를 사용한다. 생성 응답이 유실되면 실제 자원을 조회하고, 적용 여부가 불명확한 요청은 반복 전송하지 않는다. 미적용 근거를 확인했을 때만 다음 명령으로 재조정한다.

```sh
handrail setup-resolve OPERATION_ID --evidence '실제 자원과 요청 이력을 확인한 근거'
```

이는 로컬 기록만 변경한다. 이후 원래 `init` 또는 `sync`를 재실행한다. 명확한 권한 거절은 실제 권한을 해결한 뒤 재시도할 수 있다.

## 경로 확인과 호환성

`handrail locate` 또는 `handrail skill-path`는 로드된 runtime에서 정확한 skill·launcher·plugin 경로와 버전을 반환한다. 에이전트는 캐시 경로를 조립하지 않는다. Codex 스킬 목록의 경로 해석은 외부 제품의 영역이므로 잘못된 경로가 제공돼도 이 명령으로 복구하도록 스킬 설명에 명시했다.

기존 연결·바인딩·작업 이력은 보존한다. 기존 단일 보드의 카드를 자동 이동하지 않는다. 신규 Work 카드는 명시한 보드 또는 부모 보드를 사용하며, 고급 `bind`는 명시 ID·매핑 인터페이스로 남긴다.

이번 변경은 사용자 재테스트용 개발 버전이다. 실제 보드 생성과 전체 구현 워크플로우의 수락 테스트는 미실시다. API 구현은 이 호스트 Vikunja 2.6.0의 공개 OpenAPI 명세와 [공식 v2 문서](https://vikunja.io/docs/api-v2/)를 기준으로 한다.
