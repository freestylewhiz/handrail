- 대상 버전: `1.0.0-alpha.1`

- 제공된 안내: `setup --name <연결이름> --url <Vikunja_URL>`

  - [x] HTTP URL을 사용하는 경우 `--allow-insecure-http`를 포함한 완전한 설정 명령을 안내하도록 개선

## CHK-015 — 구현 요청 시 기본 작업보드 자동 준비

- 상태: 개선 요구 접수 / 미구현 (2026-10-08)
- 대상 버전: `1.0.0-alpha.5`
- 사용자 관찰: 초기 설정에서는 부모 보드가 연결되지만, 실제 작업 카드를 담을 하위 작업보드가 없는 상태로 구현 요청을 시작할 수 있음.
- 사용자 요구: 기획 카드에 따른 구현·작업 요청 시 작업보드가 없으면 부모 보드 아래 `default`를 생성하고 이어서 작업할 수 있도록 지원.
- 현재 구현과의 차이: 작업보드 배정이 없으면 작업 카드를 부모 보드로 보내는 경로가 있다. 작업 시작 전에 작업보드를 준비하고 배정을 확정하는 흐름이 필요함.
- 설계 방향:
  - 부모 보드에는 기획·Summary를, 작업보드에는 Work 카드를 기록한다. `default`는 부모 보드 아래 여러 기획이 공유하며, 기획별·모델별로 자동 증식시키지 않는다.
  - 초기 설정과 기획 카드 작성만으로 생성하지 않는다. 사용자가 실제 구현을 요청할 때 필요한 기본 작업보드를 준비한다.
  - 배정 우선순위는 기존 카드 위치 → Work 명시 배정 → Plan 명시 배정 → 등록된 기본 작업보드다. 작업보드가 없으면 `default`를 생성·등록한다. 기존 하위 보드 중 어느 것을 쓸지 불명확하면 기존 보드 선택 또는 `default` 생성을 한 번 확인하고 기록한다.
  - 작업보드와 수행자 배정은 독립적으로 관리한다. 조율자 동일 모델 또는 사용자가 지정한 다른 모델의 작업자가 같은 보드를 사용할 수 있다(CHK-016 참조).
  - `board`가 생성·등록·복구를 담당하고, `application`이 보드 준비 → 작업 카드 등록 → 작업자 실행을 연결한다. 동기화 훅은 결정된 배정을 사용한다.
- 수용 기준:
  - [ ] 작업보드가 없는 상태의 구현 요청에서 `default`와 Todo/Doing/Done 열을 준비하고 부모 관계·기본 보드 매핑·생성 이력을 기록
  - [ ] 준비 결과와 작업 카드 등록을 확인한 뒤 실행하며, 승인된 범위의 보드 준비에 같은 의도를 반복 질문하지 않음
  - [ ] 명시적 보드 배정과 기존 카드 위치를 보존하고, 기본 보드 변경은 이후 새 작업에 적용
  - [ ] 동시 요청·부분 성공·응답 유실 시 동일 생성 의도로 조회·재개하여 보드와 카드 중복 방지
  - [ ] Handrail 관리 보드는 재사용하고, 별도로 만든 동명 보드는 사용자 선택 없이 인수하지 않음
  - [ ] 권한 부족·삭제·연결 범위 변경 등으로 준비에 실패하면 남은 조치와 재개 방법을 안내하며 부모 보드로 임의 배치하지 않음
  - [ ] 기획 완료 후에도 공용 작업보드와 카드 이력을 보존하고 AgentRoom 정리는 별도로 처리
- 연관 항목: CHK-006 보드 구성 기능, CHK-014 반복 승인 최소화, CHK-016 기본 작업자 선택.
- 최초 접수 당시 처리 범위: 체크리스트 등록만 수행. 보드 생성·작업자 실행·코드 변경은 수행하지 않음.

## CHK-016 — 조율자 동일 모델을 기본 Herdr 작업자로 사용

- 상태: 개선 요구 접수 / 미구현 (2026-10-08)
- 사용자 제안: 조율자가 직접 작업해야 하는 경우에도 Herdr 스페이스에서 조율자와 동일한 모델의 에이전트를 사용하여 구현하도록 할 것.
- 설계 방향:
  - 일반적인 “구현해줘”, “네가 작업해줘” 요청은 조율자가 기획·분배·진행 관리·결과 검토를 담당하고, 동일 모델의 별도 Herdr 작업자가 구현하는 흐름으로 처리한다.
  - 사용자의 명시적 제공자·모델·추론 수준 지정이나 적용 범위가 유효한 기존 선택을 우선한다. 미지정 시 확인된 조율자의 제공자·모델·추론 수준을 기본값으로 사용한다.
  - 조율자 직접 구현을 위한 별도 실행 경로 제안은 이 방식으로 대체하고, 기존 Herdr 실행·검토·통합·근거·완료 관리 절차를 공통 적용한다.
  - 보드 추가·카드 상태 변경 등 Handrail 관리 작업은 조율자가 CLI로 처리하며, 이를 위해 구현 작업자를 실행하지 않는다.
- 수용 기준:
  - [ ] 기본 정책과 실제 선택 근거를 기록하고, 동일 범위에서 모델 선택이나 이미 승인한 실행 범위를 반복 질문하지 않음
  - [ ] 조율자 설정을 확인할 수 없거나 해당 모델을 실행할 수 없으면 필요한 선택만 요청하며 다른 모델로 임의 대체하지 않음
  - [ ] 별도 세션에 기획·완료 기준·사용자 제약·관련 Summary의 필요한 영역·작업 위치를 명시적으로 전달
  - [ ] 같은 작업을 이어가는 경우 기존 실행을 확인·재개하고, 새 작업·재시도·교체는 구분된 실행 이력으로 추적하며 중복 작업자 실행 방지
  - [ ] 작업 카드에서 조율자와 실제 구현 작업자, 제공자·모델·추론 수준, 실행 기록을 추적할 수 있음
  - [ ] 기본 작업보드 준비와 카드 등록 이후 해당 기획의 AgentRoom에서 실행하고, 검토·통합·검증 근거를 거쳐 사용자에게 기획 리뷰를 요청
