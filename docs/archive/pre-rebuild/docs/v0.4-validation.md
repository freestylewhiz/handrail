# v0.4.0 구현·검증 기록

일자: 2026-10-01. 최종 배포 형태는 Python runtime과 스킬을 포함한 Codex 플러그인 ZIP이다. 이 기록은 로컬 구현·검증·빌드에 대한 것이며, GitHub 게시나 호스트 플러그인 설치를 뜻하지 않는다.

## 구현

- 프로젝트·전역 capability grant와 승인 이력, 갱신·만료·철회.
- 복수 부모 계획의 명세·검증·Review 회차에 묶인 위임과 실행 한도.
- 하위 명세의 `--delegated` 등록, 별도 사용자 동의 문구를 만들지 않는 run 권한 파생.
- 필요한 workflow와 provider 적용 가능성을 실행 전 확인. 기존 run에는 원래 권한을 유지하고, 승인된 확대가 그 범위를 포함하면 계속 사용.
- Codex/Cursor 추가 경로·네트워크 어댑터, 조율자 호스트의 요구 경로와 네트워크 안내.
- 실행 전 dependency copy/install, 명시적 `orchestrator-host` 설치 경계.
- 실패 후보의 해시 snapshot·복원 후 시작하는 `run retry`.
- 회차별 패킷 보존과 CONTEXT.md 재생성, 결과 JSON 템플릿, 보조 검증 `run check`.
- 활동 메타데이터, 준비 로그, 다음 조치. 워커 종료 뒤 출력 파이프가 남아도 무한 대기하지 않는 수집.
- CLI 도움말, 번들 스킬, 사용법, 백로그 구현 범위 갱신.

## 검증 방법

최종 결과: **146개 테스트 통과, 건너뛴 테스트 0개**. 임시 Vikunja를 연결한 전체 실행은 93.940초에 완료됐다. 플러그인/스킬 형식 검사와 예비 배포물 검증도 통과했다.

`python3 -m unittest discover -s tests -q`는 private permission store, 실제 임시 Git/worktree, 위조·만료·철회·갱신, 여러 계획과 하위 작업, seed 복원 순서, CLI 및 배포 무결성 회귀 테스트를 수행한다.

추가로 별도 임시 Vikunja 2.6.0 컨테이너를 127.0.0.1의 임시 포트에 실행하고 `HANDRAIL_TEST_VIKUNJA_URL`을 지정하여 기존 one-run 경로와 새 저장 권한 경로를 모두 검사했다. 사용자의 기존 서버와 토이 프로젝트는 테스트 대상이 아니다. 실제 Vikunja API·supervisor·Git 검증/통합/Review는 실행하지만 워커는 결정적 테스트 CLI를 사용한다. 실제 유료 모델 호출이나 모든 호스트 sandbox 조합의 검증으로 해석하지 않는다.

플러그인·스킬 검증기, Python 구문 검사, `git diff --check`, ZIP/manifest/체크섬 검사 및 격리된 번들 launcher의 버전·도움말 실행을 확인한다. 빌드의 `source_tree_dirty=false`와 source revision은 최종 커밋에서 다시 생성한 `build-info.json`으로 확인한다.

## 한계와 후속 항목

- Handrail은 이미 실행 중인 조율자의 상위 sandbox나 조직 권한을 해제하지 않는다. 사전 호스트 설정이 필요할 수 있다.
- Cursor 사용자/팀 설정과의 병합으로 강제 network disabled는 지원하지 않는다. 실효 권한 전체 자동 검사는 제공하지 않는다.
- 설치·검증 명령은 조율자 호스트에서 실행되며 worker sandbox 안에서 실행된다고 보장하지 않는다.
- copy 준비는 manifest 일치만 검사하며 설치된 node_modules의 lockfile 일치 증명은 아니다.
- 자동 형식 복구, 목적지별 네트워크 제한, 상주 계획 조율자, 작업 Done 시점/부모 Review 열 생성 정책 변경은 이번 권한 릴리스 범위에 포함하지 않았다.
