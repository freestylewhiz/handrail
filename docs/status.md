# 구현 상태 — 1.0.0a6

현재 개발 버전은 **alpha.6**, 브랜치는 `main`이다. 2026-10-08 사용자 요청으로 현재 작업 결과를 최초 커밋으로 삼고 이전 로컬 Git 이력·브랜치를 제거했다. 기존 연결 worktree는 파일을 보존한 채 Git 연결을 해제했고 원격 연결 설정은 유지했다. 원격 저장소에는 push하지 않았다. 체크리스트 DEV-01~10 종료 후 DEV-11·12를 추가했으며 DEV-11은 설계/구현 대기, DEV-12는 소스·검증 완료/호스트 수용 대기다. 이력 초기화가 미완료 개발이나 호스트 수용을 완료시키지는 않는다.

## Summary 분리 — DEV-12 소스 반영

새 Summary의 schema 2는 프로젝트 결과와 Handrail 수행 이슈를 언어별 본문·Agent Context에서 분리한다. 이슈의 관측·영향·복구·현재 상태·근거를 검증하며 `summary list --issues`와 선택 읽기를 지원한다. 기존 schema 1·원문·이력·기본 작업자 프로젝트 참조는 유지한다. 반복 승인 최소화 원칙은 프로젝트 규약·철학·공통 스킬에 기록했다.

회귀 테스트 10개가 소스 및 `dist/alpha6-summary-areas/` 검증용 번들에서 각각 통과했고, 61개 모듈의 정적 import 검사도 통과했다. 실제 보드나 호스트 설치는 변경하지 않았다. 이 번들은 기존 설치 버전 식별자를 유지한 로컬 검증 산출물이며 배포 전 고유 버전 부여·호스트 수용은 [D12-S06](checklist-v1-host-test.md#10-dev-12--summary-분리와-handrail-개선-근거-축적)으로 남긴다. 현재 체크됨 147개·열림 22개이며 기존 종료 142개와 DEV-11 21개는 그대로다.

## 신규 설계 — DEV-11

[저장소 최초 승인과 조율자 자동 후속 실행](designs/dev-11-project-automation.md)을 설계하고 [체크리스트](checklist-v1-host-test.md#9-신규-개발--dev-11)에 등록했다. 저장소 운영 정책의 재사용, 양쪽 역할의 권한 준비, 작업자 완료 후 실제 검토·병합·테스트·수정·Review 보고, 지원 호스트에서 턴 종료 후 조율자 재개가 대상이다.

**설계 문서만 반영했으며 구현·실행 검증·호스트 정책 적용·재설치는 대기다.** 현재 tick의 다음 행동 안내와 `host_wakeup=unavailable` 제약은 그대로다. DEV-01~10의 종료 기록이나 기존 검증 근거는 변경하지 않는다.

RC03 조율자 회고와 개발 책임자 심사를 거쳐 [코드 수정 7개·스킬/절차 보완 2개](checklist-v1-host-test.md#9-신규-개발--dev-11)를 DEV-11의 R01~09로 추가했다. DEV-11 안에서는 전체 수용 A01~12와 합쳐 21개가 열려 있으며 기존 종료 142개는 유지한다. 신원·채널 권한·계약 전환을 먼저 보완하고 진단·상태 확인 후 자동화에 연결한다. 이는 개발 추적 등록이며 RC03의 수동 복구 성공을 Handrail 수정 완료로 처리하지 않는다.

## 확인과 설치의 구분

기존 DEV-01~10 종료 시점에는 Python 3.9 AST 구문 정적 분석과 2026-10-08 호스트 재설치를 완료했으며, 해당 범위의 자동 테스트·실제 보드/작업자 실행·네 조합 승인 측정은 미실행이었다. [체크리스트](checklist-v1-host-test.md)의 기존 DEV-01~10은 사용자의 명시적 전체 종료 요청에 따라 닫았다. 이 과거 근거 한계는 유지하며, 이후 DEV-12의 10개 회귀 테스트 결과는 위 별도 항목으로 기록한다.

현재 호스트의 플러그인 버전은 **`1.0.0-alpha.6+codex.20261008041952`**, CLI는 `Handrail 1.0.0a6`이다. 2026-10-08 `handrail_rc_02`의 설정 실패를 분석하고 수정판으로 교체했다. 최신 빌드 및 [설치 보고서](../dist/alpha6-rc02-fix/host-install-report.json)는 `dist/alpha6-rc02-fix/`에 있다. 설치 파일 76개의 무결성, Codex 설치·활성 상태, 고정 런처와 Cursor 스킬 연결을 확인했다. 기존 alpha.6 설치물을 제거했으며 연결·바인딩·작업 이력·worktree·외부 서비스 데이터는 보존했다. 새 Codex/Cursor 세션에서 갱신된 스킬을 읽어야 한다.

같은 날 사용자의 추가 요청으로 Handrail 플러그인 등록·전체 캐시·관리 release·런처·Cursor 스킬 연결을 삭제한 뒤 같은 수정판을 새로 설치했다. 과거 Codex 설치 임시 폴더 3개와 uv의 Handrail 0.3 편집 설치 캐시 2개도 제거했다. 최신 버전만 남았으며 연결 설정·작업 이력·worktree·다른 플러그인은 보존했다. [전체 제거 후 재설치 보고서](../dist/alpha6-rc02-fix/host-clean-install-report.json)에 삭제 경로와 잔여물 확인을 기록했다.

## RC02 설정 결함 수정

alpha.6 변경 중 setup 쓰기 진단 함수 `check_writes`가 빠져, 호스트 승인 뒤 `init`이 ImportError로 중단됐다. `setup/write_access.py`로 진단을 복구하고 호스트 승인 규칙 관리와 분리했다. CLI의 내부 설치 오류 안내와 스킬의 정식 수정판 복구 절차를 추가했다.

빌드가 이름을 지정한 내부 import를 정적 분석한다. 이전 번들에서 누락 1건을 검출했고 수정 소스·번들의 내부 모듈 60개는 오류 없이 통과했다. 이는 실제 `init`이나 외부 서비스의 동작 테스트가 아니다. 대상 저장소의 설정·보드는 변경하지 않았으며 사용자 테스트로 설정을 재개한다. [원인·조치 보고서](reviews/handrail-rc-02-2026-10-08.md)에 근거를 기록했다. 기존 체크리스트 종료는 유지한다.

## 기존 사용자 확인 및 보존

2026-10-07 사용자가 CHK-001~007 최종 확인을 완료했다. 스킬 경로, HTTP 허용 안내, 간소화된 설정, 부모 Review 열, 보드 선택, 하위 보드 관리, 카드 강제 전환·보류/재개 확인은 유지한다. 기존 alpha.5 설치 보고서는 `dist/host-install-alpha5/host-install-report.json`이다.

alpha.5의 Plan 수락, Summary 카드 원본·언어/Agent Context 분리, reopen 및 close/keep 정책을 유지한다. 기존 카드 본문·기준·위치를 자동 이관하지 않고 신규 기능은 현재 명령 실행에서 적용한다. 중단된 카드 생성은 이전 전송 본문을 재사용한다. 과거 소스/문서 삭제나 기존 작업 변경을 되돌리지 않았다.

## 운영 제한

- Codex/Cursor CLI 규칙은 IDE·관리 정책에 자동 적용된다는 보장이 없다. 요청 설정과 작업자가 관측한 쓰기 결과를 구분한다.
- 쓰기 진단은 훅·서명·모든 Git 커밋의 성공이나 브랜치 격리를 보장하지 않는다. 공유 Git에는 저장소 수준 영향이 있다.
- tick은 활성 대화의 단일 확인이다. 대화 종료 후 자동 깨우기/백그라운드 감시는 구성하지 않는다. 재접속 시 미처리 inbox와 다음 행동을 복구한다.
- 프로세스 신원은 Linux /proc 및 Herdr 관측에 의존한다. 근거가 없으면 확인 불가로 남는다. 실제 대상 변경을 정상적인 정보 보강으로 취급하지 않는다.
- 번역·의미 종합·지침 충돌 판단·검증의 의미 검토는 조율자 모델이 수행한다. CLI는 형식·참조·revision·전송을 관리한다.
- 외부 API와 Herdr에는 마지막 조회/쓰기 사이의 원자적 비교가 없다. unknown 쓰기와 복수 호스트 경합에 대한 제약을 명시한다.
- 내부 grant, 호스트 정책, 사용자 최종 수락, room 정리, worktree 삭제는 각각 다른 권한이다.
- 테스트 대상 저장소/보드/방과 원격 저장소는 변경하지 않았다. 이 소스 저장소의 로컬 Git 이력 초기화는 위에 기록한 사용자의 별도 명시 요청으로 수행했다.
