# Worktree 배치 2차 교차 토의

각자 상대의 worktree-*-round1.md와 worktree-discussion-source-notes.md를 읽고 반론에 답한다. 두 모델 모두 B(repo 내부) 일괄 기본값에 반대하지만 기본 배치는 Astra가 C(승인된 개발 workspace의 영속 외부 루트), Grok은 E 정책하의 A(XDG) 무설정 기본을 권고했다.

다음 질문에 구체적인 정책으로 답하라. 읽기 전용, 토의만 수행하며 실험·수정 금지. 700~1100 단어 한국어 이내. 최종 답변 시작에 WORKTREE_ROUND2_FINAL_ASTRA 또는 WORKTREE_ROUND2_FINAL_GROK, 마지막에 동일 접미사의 WORKTREE_ROUND2_COMPLETE 표식.

1. 상대가 제기한 3개 질문에 답하고, 받아들이거나 반박한 근거를 밝힐 것.
2. 신규 사용자에게 권장할 물리적 구조와 기존 설치에서 설정이 없을 때의 동작을 구분하면 합의 가능한가? 권장 후보 C를 제시하되 확정된 개발 루트가 없으면 A를 보존하고, 실제 host 적용을 확인하는 정책에 대한 찬반.
3. 설정 없는 project-only sandbox에서 A도 C도 막히면 조율자가 어떻게 해야 하나? 매 계획마다 질문하거나 B나 /tmp로 조용히 바꾸지 않도록 초기 설정과 승인 재사용의 구체적인 흐름을 적을 것. C는 부모 경로를 임의로 권한 범위로 확장하는 안이 아니다.
4. 원본 checkout 밖 영속 경로가 목표라는 구조적 합의와, 모든 환경의 C 기본값이라는 주장을 구분할 것. B는 Git linked worktree 자체의 논리적 독립성을 반드시 파괴하는 것은 아니다. 제품 규칙 위반이라는 주장에는 정확한 조건이 필요하다.
5. Grok 1차의 git clean -fdx가 nested Git worktree를 지운다는 일반화, IDE 검색이 삭제한다는 문구, capture_seed가 .handrail 부모 경로 때문에 충돌한다는 주장은 검증되지 않았다. 실제 상대경로 기준을 읽고 필요한 부분은 정정하거나 미확정으로 남길 것. 소스 배치의 권한상 이득 자체를 우회/숨김이라고 단정하지 말 것.
6. 과도하게 넓은 명령 prefix를 권한 재사용 설계로 삼지 말 것. 정확한 자원과 검증된 작업 범위를 사용하는 제품 계약, 사용자 의도 기록, host 적용은 별개다. 파일시스템 모드만으로 sandbox 허용을 보장하지 말 것.

최종 정책은 기존 실행 경로 pinning, 신규 경로 선택 순서, private state 분리, 승인 최소화, 구현 우선순위 3개로 정리한다. 합의되지 않은 차이가 있다면 숨기지 않는다.
