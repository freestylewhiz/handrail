# 개발 체크리스트 — DEV-11 개발·DEV-12 호스트 수용 대기

2026-10-08 사용자의 “현재까지의 체크리스트를 모두 닫아줘” 요청에 따라 [DEV-01~10 체크리스트](checklist-v1-host-test.md)를 모두 종료했다. 후속 요청으로 **DEV-11·12**를 등록했다. 기존 종료 상태는 유지한다. 소스·스킬·문서·alpha.6 호스트 설치의 반영 내용과 제약은 [구현 기록](alpha6-implementation.md)에 보존한다.

## 소스 구현 완료 — DEV-12

Summary를 프로젝트 결과와 Handrail 수행 이슈로 분리하고 이슈 검색·선택 조회·근거 기록을 구현했다. 반복 승인 최소화와 이슈의 책임별 분류 원칙을 프로젝트 규약·스킬에 반영했다. schema 1 호환·수락/이력·작업자 기본 인계 분리 등 10개 테스트가 소스와 검증용 번들에서 통과했다. [D12-S01~05](checklist-v1-host-test.md#10-dev-12--summary-분리와-handrail-개선-근거-축적)는 반영 완료이며 D12-S06의 고유 배포 버전·호스트 설치·실제 보드 수용은 남아 있다. 현재 체크됨 147개(기존 종료 142+신규 5), 열림 22개다.

## 다음 개발 — DEV-11

[저장소 최초 승인과 조율자 자동 후속 실행 설계](designs/dev-11-project-automation.md)를 작성했다. 구현·검증은 대기이며 [체크리스트 9절](checklist-v1-host-test.md#9-신규-개발--dev-11)의 **전체 수용 기준 A01~12 및 RC03 보완 R01~09** 21개가 열려 있다. 수용 기준과 구체적 보완은 다른 추적 수준이며 기능 21개를 뜻하지 않는다.

RC03 선행 보완은 신원 오탐·실제 채널 권한·안전한 계약 전환(R01~03)을 한 묶음으로 수정한 뒤 실패 진단·현재 상태·증거 미등록 안내(R04~06)를 보완한다. 이 근거를 확인하고 아래 자동 후속 실행을 연결한다. 보고 도구 준비·수락 후 Summary 검토 스킬(R08~09)은 병행하며 URL 렌더링(R07)은 낮은 우선순위다. 정책 설계와 호스트 재개 지원 조사는 선행 수정과 함께 진행할 수 있다.

1. D11-01: 저장소 운영 정책과 작업 의뢰 근거, Plan/cycle별 승인 파생·차이·철회.
2. D11-02: 조율자/작업자 권한 준비, 전체 workflow 동작의 좁은 규칙, 등록 테스트 실행.
3. D11-03: 완료 수신부터 검토·병합·검증·수정·Review 보고까지 후속 실행과 통합 배치.
4. D11-04: 지속 확인·조율자 재개 어댑터, 실행 소유권·중복 방지·중단 복구. 호스트 지원 조사는 D11-01과 함께 시작한다.
5. D11-05: 실제 조합별 승인·실행·재개 검증, 스킬·문서·배포와 사용자 수용 확인.

최초 설정 후 동일 범위의 운영 재승인 0회가 목표다. 대화 종료 후 자동 재개는 실제 지원 호스트에서 별도로 검증한다. 이번 문서 변경으로 실행이나 권한 설정을 활성화하지 않는다.

[RC03 책임자 점검](reviews/handrail-rc-03-2026-10-08.md)에 따라 범용 제공자 제어 프레임워크, 피드백 예약 큐, Summary 자동 의미 수정, 대상 앱의 구현·운영 수정은 추가하지 않는다. 기존 unknown 전달 복구와 후속 차단의 비정상 종료 코드는 유지한다.

## 기존 DEV-01~10 코드 반영

1. 공통 실행·권한·완료 인계 계약과 관측 기준.
2. 고정 런처, Codex/Cursor 스킬 연결과 저장소·기능별 승인 재사용 규칙.
3. 관측 모델 선택, 작업자 경로 설정 및 자신의 sandbox에서 쓰기 진단.
4. default 작업보드 준비, 첫 카드 배정, Work Review.
5. 완료 보고·수신·검토 처리, 지속 확인·재접속 복구, Plan Review와 사용자 보고.
6. Done 이후 정리 신원 복구와 실패 종료 코드.
7. 채택 카드 양식, 유형 라벨, 부모 보드 Instruction과 참조/변경 전달.
8. 아키텍처·철학·운영·스킬·설치 문서와 alpha.6 배포 번들.

## 종료 시 확인 기록

alpha.6 호스트 재설치와 정적 분석·설치 확인은 완료했다. 아래는 종료 당시 별도 실행·확인 근거가 없었던 범위의 기록이다. 체크리스트 종료를 테스트 통과로 해석하지 않으며, 아래 내용을 열린 후속 작업으로 남기지 않는다.

- 네 조합(Codex/Cursor 조율자 × Codex/Cursor 작업자)의 실제 실행·승인 요청 수와 대기 시간.
- 새 세션의 고정 런처·스킬 버전 일치, 기존 정책 보존, 관리 정책/IDE 차이.
- 첫 쓰기 진단과 실제 커밋, 완료 알림 유실·재접속·재작업의 전체 인계.
- 기존 카드/보드/override/중단 intent 보존, Instruction 라벨 권한·수동 카드·변경 적용.
- Plan Review 사용자 보고, 수락·Summary, 늦은 세션 ID·Cursor 신원·Done 이후 정리.
- 재설치 후 사용자 수용 확인.

기존 CHK-001~007의 사용자 최종 확인은 유지한다. Git 전용 broker 등 보류 항목과 archive/reviews의 과거 backlog는 이번 구현에 포함하지 않는다.

이후 테스트에서 발견되는 문제나 새로운 요청은 새 체크리스트 항목으로 등록한다.

후속 RC02 결함은 [별도 분석·수정 기록](reviews/handrail-rc-02-2026-10-08.md)으로 관리한다. 이전 DEV-01~10의 사용자 요청 종료를 변경하지 않는다.
